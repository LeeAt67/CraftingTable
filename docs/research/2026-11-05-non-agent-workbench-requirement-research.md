## 1. 目的

Agent 之外的“今日工作台”目前只有一条最小闭环：加载今日条目、Quick Capture 新建、完成/取消完成、Light / Dark 主题。侧栏筛选、编辑、安排时间、删除、日期切换和设置页都还没有真实行为。

本文调研这些缺口，给出可验收的判定标准、优先级建议、边界和待决策问题。**需求条目与当前状态不在这里维护**，见 [需求索引](../requirements.md)；本文只提供每条需求背后的依据。

## 3. 需求原则

1. 单用户、本地优先：不引入账号、权限、云同步和多端协作。
2. 不改 Agent 边界：非 Agent 需求不得修改 Agent 的 HTTP 契约、Store 所有权、Run 生命周期和数据库迁移语义。
3. 时间统一：数据库存 UTC，界面按用户本地时区展示，日界按用户时区计算。
4. 单一事实源：业务数据只进 `todayStore`；筛选、选中日期等视图状态单独建模，不复制条目。
5. 错误是数据：Model 返回可识别的错误，Effect 负责映射提示，View 不解析错误字符串。
6. 先设计后实现：每条需求先补设计/ADR，再补失败测试和最小实现。
7. 保持现有 HTTP 风格：继续使用 `GET` / `POST` 和统一响应封套；若要改 REST，必须单独出 ADR 并迁移测试。

### 3.1 优先级定义

| 优先级 | 含义 |
| --- | --- |
| P0 | 阻塞“今日”日常闭环，下一批次必须完成 |
| P1 | 影响可靠性或数据安全，P0 完成后进入 |
| P2 | 体验增强，可延后且不改变数据契约 |

### 3.2 编号规则

`T` 今日工作台、`S` 设置、`N` 导航与布局、`A` API 与数据、`Q` 质量与非功能。编号一经使用不复用。

## 4. 需求清单

### EPIC T：今日工作台

#### T-01 日期导航（P0）

**需求**：用户可以在“昨天 / 今天 / 明天”之间切换，也可以在日历中选择日期；当前日期必须体现在页面标题和 URL 中。

**验收标准**：

- [ ] 页面提供“上一天 / 今天 / 下一天”控件，键盘可操作。
- [ ] URL 使用 `/#/?date=YYYY-MM-DD`；刷新、前进、后退后仍停留在同一日期。
- [ ] 非今天时标题显示“昨天 / 明天 / 具体日期”，不再显示“今日”。
- [ ] 切换日期时先展示加载骨架，失败时保留原日期并提供重试。
- [ ] 空日期显示专用空状态，不显示“今天还没有安排”。
- [ ] 数据库查询使用用户时区的 `[00:00, 24:00)` 区间，服务端不再自己决定日界。

**依赖**：A-01、A-03。

#### T-02 侧栏筛选真实生效（P0）

**需求**：侧栏的“全部 / 已安排 / 已完成”和分类按钮成为真实筛选器，选中状态清晰且可恢复。

**验收标准**：

- [ ] 点击筛选项只改变列表，不重新请求服务端。
- [ ] 选中项有 `aria-pressed` 或 `aria-current`，视觉状态与导航一致。
- [ ] 筛选条件写入 URL 查询参数，例如 `?filter=planned&category=work`。
- [ ] 多个筛选条件允许组合：状态筛选 + 分类筛选。
- [ ] 计数随当前日期和分类联动，不统计其他日期的条目。
- [ ] 筛选结果为空时给出“清除筛选”入口。
- [ ] 刷新页面后筛选条件保留；非法参数回退到“全部”。

**依赖**：T-01。

#### T-03 条目编辑（P0）

**需求**：用户可以编辑条目的标题、描述、分类、开始时间和结束时间，并看到保存结果。

**验收标准**：

- [ ] 列表条目提供编辑入口，打开对话框并预填当前值。
- [ ] 标题必填、去首尾空格、最多 200 字符；描述最多 2000 字符；错误提示与后端一致。
- [ ] 分类只能从现有分类中选择，允许清空。
- [ ] 结束时间不得早于开始时间；只填结束时间时给出明确提示。
- [ ] 保存期间按钮禁用，重复点击不产生重复请求。
- [ ] 成功后原地更新条目并提示“已保存”；失败保留对话框内容和已输入值。
- [ ] 编辑不改变 `createdAt`，只更新 `updatedAt`；完成状态不被编辑重置。

**依赖**：A-03、A-04（并发控制可在 P1 补）。

#### T-04 删除条目与撤销（P1）

**需求**：用户可以删除误建条目，并在短时间内撤销。

**验收标准**：

- [ ] 删除前二次确认，确认文案包含条目标题。
- [ ] 删除成功后条目从列表移除，并提示“已删除”且提供“撤销”。
- [ ] 撤销窗口内恢复原条目及其完成状态、分类和时间。
- [ ] 删除不存在的条目返回 `NOT_FOUND`，界面提示后刷新列表。
- [ ] 选择软删除时，撤销恢复同一 `id`，且不产生重复条目。

**依赖**：A-02。

#### T-05 安排与调整时间（P0）

**需求**：未安排任务可以安排到具体时间段，已安排任务可以改期或取消安排。

**验收标准**：

- [ ] 未安排任务提供“安排时间”入口，保存后状态变为 `planned` 并按时间重新排序。
- [ ] 取消安排后状态回到 `unplanned`，`startAt`、`endAt` 清空。
- [ ] 时间选择按用户本地时区输入，提交时转换为 UTC。
- [ ] 允许只填开始时间；填写结束时间时必须晚于开始时间。
- [ ] 安排操作与完成状态互不覆盖：已完成条目改期后仍为 `done`。

**依赖**：T-03、A-03。

#### T-06 时间流排序与分区（P1）

**需求**：时间流按可解释的规则排序，并区分“已安排”“未安排”“已完成”。

**验收标准**：

- [ ] 已安排条目按 `startAt` 升序排列；同一时刻按 `createdAt` 升序。
- [ ] 未安排条目单独分区，按 `createdAt` 降序排列。
- [ ] 已完成条目默认沉底，可通过设置或筛选查看。
- [ ] 分区标题可被屏幕阅读器识别，不依赖纯视觉分隔。
- [ ] 排序规则在前端实现一次，服务端不再返回第二套隐式顺序；或明确由服务端排序并在契约中固定。

**依赖**：T-02。

#### T-07 专注时长口径（P1）

**需求**：摘要中的“专注”必须有唯一、可解释的口径，并处理异常数据。

**验收标准**：

- [ ] 口径明确为“当日已安排日程的区间总时长”，并在界面 tooltip 或设置页说明。
- [ ] 只统计 `startAt` 和 `endAt` 都存在且 `endAt > startAt` 的条目。
- [ ] 结束时间早于开始时间的脏数据不计入，且不产生负数。
- [ ] 跨天区间按与当日重叠部分计算，不整段计入。
- [ ] 分钟数向下取整；小于 1 分钟显示“<1 分钟”。
- [ ] 口径变化时同步更新单元测试和 README 或设计文档。

**依赖**：A-03。

#### T-08 完成度口径统一（P1）

**需求**：侧栏完成度、摘要和筛选使用同一套计数规则。

**验收标准**：

- [ ] 完成度分母为当前日期、当前分类下的全部条目，不包含其他日期。
- [ ] 已完成条目数、已安排条目数、待办数在侧栏、摘要和筛选中一致。
- [ ] 空列表完成度显示 0%，不显示 `NaN`。
- [ ] 计数逻辑抽成纯函数并有单元测试，不在多个组件重复实现。

**依赖**：T-02、T-07。

#### T-09 Quick Capture 增强（P2）

**需求**：快速捕获支持最少操作完成“记下来 + 归类和安排”。

**验收标准**：

- [ ] 支持 `Cmd/Ctrl + Enter` 提交、`Esc` 关闭。
- [ ] 可选分类和可选时间；不填时创建未安排任务。
- [ ] 提交成功后清空输入并保持对话框打开，支持连续录入；提供关闭入口。
- [ ] 输入草稿在关闭后保留，直到提交成功或手动清空。
- [ ] 新建失败时保留输入并允许重试。

**依赖**：T-03。

#### T-10 加载、空与错误状态（P0）

**需求**：每种状态都有明确、可恢复的界面，不影响其他区域。

**验收标准**：

- [ ] 首次加载使用骨架屏；切换日期或筛选不闪回全屏骨架。
- [ ] 网络失败展示错误信息和“重试”，重试成功后恢复。
- [ ] 单个操作失败不清空已有列表；列表保留最后成功数据。
- [ ] 空状态区分“该日期没有条目”和“筛选后没有结果”。
- [ ] Toast 不替代行内错误；关键错误同时出现在页面中。
- [ ] 所有异步操作有防重复提交保护。

**依赖**：无。

#### T-11 键盘与快捷操作（P2）

**需求**：高频操作可只用键盘完成。

**验收标准**：

- [ ] 提供“新建条目”快捷键，且不与浏览器或输入法冲突。
- [ ] `j` / `k` 或上下方向键可在时间流中移动焦点；`Enter` 完成，`e` 编辑。
- [ ] 快捷键在输入框聚焦时不触发。
- [ ] 快捷键清单可在设置页或帮助浮层查看。
- [ ] 焦点移动有可见焦点环，且不破坏屏幕阅读器顺序。

**依赖**：T-03、Q-01。

### EPIC S：设置

#### S-01 设置页信息架构（P0）

**需求**：设置页从占位改为分组设置页，至少包含“外观”“数据”“关于”。

**验收标准**：

- [ ] 设置页有稳定标题、分组导航和“返回今日”。
- [ ] 分组在小屏折叠为单列，不出现横向滚动。
- [ ] 每个设置项有标签、当前值、说明和保存反馈。
- [ ] 未实现的设置项不显示禁用假开关。
- [ ] 设置页不读写 Agent 状态。

#### S-02 外观设置（P0）

**需求**：用户可以选择“浅色 / 深色 / 跟随系统”，并立即生效。

**验收标准**：

- [ ] 三选一控件，当前值可读且可键盘操作。
- [ ] 选择“跟随系统”时监听 `prefers-color-scheme` 变化并实时切换。
- [ ] 选择结果持久化；刷新后保持，且首屏不出现错误主题闪烁。
- [ ] 无 JavaScript 或存储不可用时回退到浅色，不影响页面可读性。
- [ ] 旧键 `leeat-theme` 的值可迁移到新键，迁移只执行一次。
- [ ] 主题切换不重建 Store、不重新请求今日数据。

#### S-03 偏好设置（P2）

**需求**：允许用户调整与日期、时间展示相关的偏好。

**验收标准**：

- [ ] 可设置每周起始日（周一 / 周日），仅影响后续周视图或日期选择器。
- [ ] 可设置 12 / 24 小时制，时间流与表单同步生效。
- [ ] 可设置默认分类，Quick Capture 新建时使用该值。
- [ ] 偏好保存后立即生效，不需要刷新。
- [ ] 偏好缺省值与当前行为一致，升级用户无感知。

#### S-04 数据管理（P1）

**需求**：用户可以了解数据存放位置，并导出或备份数据。

**验收标准**：

- [ ] 显示当前数据库路径（桌面阶段）或“本地 SQLite”说明（Web 阶段），不显示密钥。
- [ ] 支持导出 JSON，包含条目、分类和导出时间；文件名带日期。
- [ ] 导出不包含 Agent 会话内容和模型配置。
- [ ] 导入前校验版本和结构，失败时不写入任何数据。
- [ ] 恢复操作需二次确认，并提示会覆盖当前数据。
- [ ] 导出/导入在桌面进程中验证，不以浏览器下载代替桌面验收。

**依赖**：A-06、桌面运行容器。

#### S-05 关于与诊断（P2）

**需求**：提供版本、构建信息和可复制的诊断信息。

**验收标准**：

- [ ] 显示应用版本、构建时间和运行模式（Desktop / Web）。
- [ ] 诊断信息包含服务健康状态和数据库迁移版本，不包含 API Key、Token、用户消息正文。
- [ ] 提供“复制诊断信息”按钮，并提示复制结果。
- [ ] 诊断请求失败时不阻塞设置页其他功能。

#### S-06 设置持久化方案（P0）

**需求**：明确设置存放在前端还是服务端，并固定契约。

**验收标准**：

- [ ] 产出决策记录，说明本地 `localStorage`、服务端 `settings` 表和混合方案的取舍。
- [ ] 若使用服务端存储，新增独立迁移，不改动 `items`、`categories` 和 Agent 表语义。
- [ ] 若使用本地存储，说明多窗口和桌面/浏览器切换时的行为。
- [ ] 设置读取失败不阻塞今日页；使用默认值并提示一次。
- [ ] 设置变更不进入 Agent 事件流和 Agent Store。

### EPIC N：导航与布局

#### N-01 导航激活状态与页面标题一致（P1）

**需求**：一级导航、页面标题和 `aria-current` 始终对应。

**验收标准**：

- [ ] 今日、Agent、设置三个入口的激活样式与 URL 一致。
- [ ] 深链直接打开时激活状态正确，不依赖点击过导航。
- [ ] 页面 `h1` 与导航名称一致；图标按钮有 `aria-label`。
- [ ] 主题按钮和导航按钮的焦点顺序符合视觉顺序。

#### N-02 深链与浏览器历史（P1）

**需求**：日期、筛选和条目对话框可通过 URL 恢复或关闭。

**验收标准**：

- [ ] 日期和筛选写入查询参数，使用 `replace` 还是 `push` 有明确规则。
- [ ] 浏览器后退可撤销筛选和日期切换，不产生重复历史记录。
- [ ] 刷新后恢复到相同视图；非法参数回退且不报错。
- [ ] 打开条目编辑对话框时可关闭，返回后列表状态不变。

#### N-03 窄屏侧栏（P2）

**需求**：窄屏下侧栏内容可访问，不挤压主内容。

**验收标准**：

- [ ] 390px 下侧栏可展开为抽屉或浮层，关闭后焦点回到触发按钮。
- [ ] 抽屉打开时背景不可滚动，`Esc` 可关闭。
- [ ] 展开状态不写入 URL；刷新后默认收起。
- [ ] 不出现横向滚动，触摸目标不小于 44×44px。

#### N-04 跳过导航与焦点管理（P1）

**需求**：键盘和屏幕阅读器用户可以跳过导航直达主内容。

**验收标准**：

- [ ] 页面首个可聚焦元素为“跳到主要内容”，激活后焦点进入 `main`。
- [ ] 路由切换后焦点移动到页面标题，并有可感知提示。
- [ ] 所有交互元素有可见焦点环，对比度满足 WCAG AA。
- [ ] 对话框关闭后焦点返回触发元素。

### EPIC A：API 与数据

#### A-01 按日期查询（P0）

**需求**：`GET /api/v1/today` 支持指定日期和时区，返回该本地日的条目。

**验收标准**：

- [ ] 支持 `?date=YYYY-MM-DD&tz=Asia/Shanghai`；缺省时使用用户当前本地日。
- [ ] 非法日期或非法时区返回 `VALIDATION_ERROR`，不返回 500。
- [ ] 服务端按 `[本地日 00:00, 次日 00:00)` 转换为 UTC 查询。
- [ ] 响应不因服务端进程时区变化而改变。
- [ ] 集成测试覆盖跨时区、夏令时切换日和非法参数。

#### A-02 删除条目（P1）

**需求**：提供删除条目的 HTTP 入口，并定义幂等语义。

**验收标准**：

- [ ] 新增 `POST /api/v1/item/delete`，请求体为 `{ "id": "..." }`。
- [ ] 删除成功返回 `{ "data": { "id": "..." } }`；不存在返回 `NOT_FOUND`。
- [ ] 重复删除同一 `id` 的响应语义固定（幂等成功或稳定 `NOT_FOUND`），并有测试。
- [ ] 删除条目不影响分类和 Agent 数据。
- [ ] 软删除时列表查询排除已删除条目，撤销接口可恢复。

#### A-03 时间语义与时区契约（P0）

**需求**：前后端对时间字段的含义、格式和日界有唯一约定。

**验收标准**：

- [ ] 所有时间字段使用 RFC 3339 UTC 字符串；输入允许带偏移量并统一转换。
- [ ] 契约文档说明 `startAt`、`endAt`、`completedAt`、`createdAt`、`updatedAt` 的语义。
- [ ] 只填 `endAt` 不填 `startAt` 的请求被拒绝，或明确允许并定义展示。
- [ ] `endAt <= startAt` 返回 `VALIDATION_ERROR`。
- [ ] 前端格式化统一走一个工具函数，不散落 `Intl.DateTimeFormat`。
- [ ] 测试覆盖 UTC 存储、本地展示、跨日区间和夏令时。

#### A-04 更新并发控制（P2）

**需求**：两个窗口同时编辑同一条目时，不静默覆盖。

**验收标准**：

- [ ] 更新请求携带客户端读取到的 `updatedAt` 或版本号。
- [ ] 版本不匹配返回 `CONFLICT`，附带当前条目。
- [ ] 前端提示“条目已在其他窗口修改”，允许刷新或覆盖。
- [ ] 冲突不产生部分写入。

#### A-05 分类管理（P2）

**需求**：用户可以新增、重命名、改色和删除分类。

**验收标准**：

- [ ] 分类名称必填、唯一、去首尾空格，长度上限明确。
- [ ] 颜色使用受支持格式并做对比度校验。
- [ ] 删除分类前提示受影响条目数量；删除后条目变为未分类，不级联删除条目。
- [ ] 分类变更后今日页和筛选同步刷新。
- [ ] 分类管理接口不影响 Agent 会话分类或标签。

#### A-06 错误码表（P1）

**需求**：前后端共享一份错误码与用户提示映射。

**验收标准**：

- [ ] 错误码至少包含 `VALIDATION_ERROR`、`NOT_FOUND`、`CONFLICT`、`INTERNAL_ERROR`、`UNAVAILABLE`。
- [ ] 每个错误码定义 HTTP 状态、`kind`、`retryable` 和默认中文提示。
- [ ] 前端按 `code` 映射提示，不直接展示后端原始 `message`。
- [ ] 未知错误码回退到通用提示，并保留 `requestId` 便于排查。
- [ ] 错误映射有单元测试，新增错误码必须同步测试。

#### A-07 写请求幂等（P2）

**需求**：今日模块的写请求支持客户端请求标识，避免重试产生重复条目。

**验收标准**：

- [ ] 创建、更新、删除支持可选 `clientRequestId`。
- [ ] 相同标识和相同内容重复提交返回首次结果。
- [ ] 相同标识不同内容返回 `CONFLICT`。
- [ ] 幂等记录有清理策略，不无限增长。
- [ ] 复用 Agent 的幂等语义时，不共享 Agent 的存储表和错误码命名空间。

### EPIC Q：质量与非功能

#### Q-01 可访问性基线（P0）

**需求**：今日、设置和导航达到 WCAG 2.1 AA 的基本要求。

**验收标准**：

- [ ] 所有图标按钮有可读名称，装饰性图标 `aria-hidden="true"`。
- [ ] 文本与背景对比度不低于 4.5:1，大文本不低于 3:1。
- [ ] 状态变化（加载完成、保存成功、删除）通过 `aria-live="polite"` 播报。
- [ ] 仅用键盘可以完成“新建 → 编辑 → 完成 → 删除 → 撤销”。
- [ ] 200% 缩放和 390px 宽度下不丢失内容和操作。
- [ ] 自动化可访问性检查纳入 E2E 或单元测试。

#### Q-02 响应式与触摸（P1）

**需求**：390 / 768 / 1024 / 1440px 布局稳定，触摸操作可用。

**验收标准**：

- [ ] 四个宽度均无全局横向滚动。
- [ ] 侧栏在窄屏仍可访问，主内容不被永久挤压。
- [ ] 可点击区域不小于 44×44px（移动端）。
- [ ] 对话框在软键盘弹出时仍可滚动到提交按钮。
- [ ] 文本不因固定高度被截断。

#### Q-03 性能预算（P2）

**需求**：常用视图在个人数据规模下保持流畅。

**验收标准**：

- [ ] 今日页首屏（本地服务）可交互时间小于 1.5s。
- [ ] 500 条条目时滚动不卡顿；超过阈值时引入虚拟列表。
- [ ] 单次切换筛选不触发网络请求。
- [ ] 不因摘要或计数重复遍历导致明显重渲染。
- [ ] 构建产物体积有基线记录，新增依赖需说明理由。

#### Q-04 观测与隐私日志（P1）

**需求**：出错时可定位，但日志不泄露内容。

**验收标准**：

- [ ] 前端错误上报包含 `requestId`、路由和错误码，不包含条目标题和描述。
- [ ] 服务端日志不记录数据库路径、模型 Key、Token 和完整请求体。
- [ ] 慢请求有阈值日志，可按 `requestId` 关联前后端。
- [ ] 用户可在诊断页看到最近错误码，不显示原始堆栈。
- [ ] 日志脱敏规则有测试或检查脚本。

#### Q-05 测试基线（P0）

**需求**：每条 P0 需求都有对应验收测试，失败路径优先。

**验收标准**：

- [ ] 今日模块的创建、编辑、删除、完成、筛选、日期切换、空状态和错误重试都有 E2E。
- [ ] 集成测试覆盖日期参数、时区、校验错误和删除语义。
- [ ] 单元测试覆盖排序、计数、专注时长和错误映射纯函数。
- [ ] 设置页覆盖主题切换、偏好持久化和旧键迁移。
- [ ] `pnpm typecheck`、`pnpm test`、`pnpm test:go`、`pnpm test:e2e` 全部通过。
- [ ] 新增测试不依赖真实模型或外部网络。

## 6. 验收场景样例

### 6.1 日期切换

```text
Given 用户位于本地时区 Asia/Shanghai，今天是 2026-11-05
When 用户点击“下一天”
Then URL 变为 /#/?date=2026-11-06
And 列表只显示本地时间 2026-11-06 00:00 至 2026-11-07 00:00 的条目
And 刷新页面后仍显示 2026-11-06
```

### 6.2 筛选组合

```text
Given 今日有 3 条工作分类条目，其中 2 条已完成
When 用户选择“已完成”并选择“工作”分类
Then 列表只显示 2 条条目
And 侧栏“已完成”计数为当前日期与分类下的 2
And URL 包含 filter=done 和 category=work
```

### 6.3 编辑校验

```text
Given 一条开始时间为 10:00 的条目
When 用户把结束时间改为 09:00 并保存
Then 对话框保持打开并提示“结束时间必须晚于开始时间”
And 服务端不收到无效请求
And 原条目保持不变
```

### 6.4 删除撤销

```text
Given 用户删除一条已完成条目
When 用户在撤销提示消失前点击“撤销”
Then 该条目以原 id、原分类、原完成状态回到列表
And 不产生重复条目
```

### 6.5 专注时长

```text
Given 今日有 09:00-10:00 和 14:00-14:30 两个日程，以及一条 08:00-07:00 的脏数据
When 用户查看摘要
Then 专注显示 90 分钟
And 脏数据不计入且不产生负数
```

## 8. 与 Agent 的边界

- 本文不新增、不修改任何 Agent 路由、`RunEvent`、SSE 协议或 Agent Store。
